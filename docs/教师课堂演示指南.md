# 教师课堂演示指南 —— 每个算法实验怎么讲、怎么演

本文档与《社会网络分析智能教学平台说明书》（`说明书_提取.txt`）逐模块对应，告诉老师：**每个算法在平台哪里进入、用什么数据演示、参数怎么调、屏幕上指给学生看什么、按说明书哪一节讲解**。

- 平台地址：部署后告知学生（内网或公网地址）；学生**免登录**即可完成全部学生侧操作。
- 教师内容管理（发布/下架模块与案例）：`/admin/`，仅教师登录。
- 本指南只讲"怎么演示"；公式推导、参数数学定义请对照说明书对应章节（下文以 **§** 标注）。

## 0. 演示前必读：三种入口与一条通用流程

| 入口 | 地址 | 适合场景 |
|---|---|---|
| 课程模块页 | `/courses` → 点进模块 | 按教学大纲顺序讲，算法卡片自带公式与版本 |
| 案例库 | `/cases` → 点进案例 | 按"提出问题→认识数据→选择方法→运行分析→解释发现→反思迁移"六步讲 |
| 自由实验室 | `/lab` | 任意算法自由实验，换数据、调参数、跑对比 |
| 课堂演示模式 | `/present/案例名`（如 `/present/zachary-karate`） | 投影全屏逐节讲解，无导航干扰 |

**实验室通用三步（所有算法都一样，先给学生建立稳定操作预期）：**

1. **第一步 准备网络**：粘贴"起点 终点 [权重]"边表或 GraphSpec JSON，或点"导入文件"上传 TXT/CSV/XLSX/JSON/GraphML/GEXF → 点"**校验图数据**"，右侧出现网络预览。
2. **第二步 选择算法**：下拉框按模块分组选择算法，查看公式与说明，按需调参数（可一键恢复默认），固定**随机种子**保证可复现。
3. **第三步 运行**：点"**运行真实算法**"→ 依次讲解 **表格（tables）/ 图表（charts）/ 网络叠加层（节点大小=指标值、边粗细=权重、节点颜色=社区）/ 警告 / 溯源（算法版本、参数哈希、种子）**。

> **讲台小技巧**：每次运行后点"下载复现 ZIP"展示给学生——里面有 result.json、parameters.json、provenance.json、GraphML 和全部结果表 CSV。告诉学生"这就是你们课程作业要交的东西"，作业可复现、可查证。匿名运行数据 2 小时自动清理，浏览器历史只存在学生本机。

**推荐演示数据速查**

| 数据 | 节点/边规模 | 最适合演示 |
|---|---|---|
| Zachary 空手道俱乐部（案例 `zachary-karate`） | 34 / 78 | 全链路：中心性、GN、多算法社区对比、蓄意攻击、HK 极化 |
| Sarasota 海豚社群（案例 `dolphins`） | 62 / 159 | 重叠社区 CPM/SLPA、链路预测对比 |
| 课堂意见网络（案例 `opinion-dynamics`） | 小型 | 观点动力学四个模型 |
| 贸易时间快照（案例 `trade-snapshots`） | 多快照 | 动态社区事件 |
| 企业关系文本（案例 `enterprise-text`） | 文本 | 文本抽取建网、导出 |
| 手敲 5~10 行边表 | 极小 | 第一次上课演示"什么是网络"（见 §4.1 例） |

## 1. 模块一：文本预处理与建网（说明书 §2）

### 1.1 中文实体关系建网 —— 算法 `中文实体关系建网`（text.extract）｜§2.1–2.2

- **入口**：课程"模块一：网络基础" → 算法卡片；或实验室下拉"模块一"。
- **演示数据**：进入案例 `enterprise-text`（企业关系文本），把案例页展示的企业关系文本复制出来；也可现场让学生口述一句"青松资本投资云帆科技，云帆科技与星河数据共建实验室"。
- **操作**：实验室 → 第一步粘贴文本点校验 → 第二步选"中文实体关系建网" → 参数保持默认（`method=rule` 规则抽取，`embedding=cosine` 共现余弦权重，`merge_threshold=0.6`）→ 运行。
- **指给学生看**：
  1. 抽出的**实体节点表**和**关系边表**（对应说明书"文本清洗→实体识别→关系抽取→频次统计"四步）；
  2. 换 `embedding=normalized`（频次归一化权重）再跑一次，对比同一条边的权重变化 → 落点讲 **§2.2 共现余弦 vs 交互频次归一化** 两种权重语义；
  3. 把 `merge_threshold` 从 0.6 调到 0（关闭合并）再跑 → 演示"同指实体合并"：如"阿里/阿里巴巴"是否被合并成一个节点。
- **讲解要点**：规则法会漏隐含关系（说明书"优缺点"栏），平台不伪造结果——抽不出就是抽不出，这也是很好的科学态度教育点。

### 1.2 图校验 —— 算法 `图校验`（graph.validate）

- **用途**：导入任何数据后先跑它，演示"脏数据长什么样"：孤立节点、自环、非法权重都会被指出。
- **课堂玩法**：故意粘一份带重复边/负权重的边表让学生看报错与警告。

### 1.3 标准图导出 —— 算法 `标准图导出`（export.graph）｜§2.3

- **操作**：用已校验的网络，参数 `format` 依次选 `xlsx` / `edgelist` / `graphml` 运行，各下载一次。
- **指给学生看**：XLSX 打开后三个工作表——**节点编号清单 / 邻接矩阵 / 边列表**（对应说明书 §2.3"三类专业软件兼容文件"），告诉学生"这份 Excel 可以直接交作业，也可以导入 Gephi/Ucinet"。

## 2. 模块二：网络搭建与可视化（说明书 §3）

可视化不是独立算法，而是贯穿实验室的**网络预览与叠加层**：

- **演示**：载入空手道俱乐部案例 → 校验后右侧预览区即是可视化。
- **指给学生看（对应 §3.2 映射规则）**：**节点大小 = 度中心性、边粗细 = 关联权重、节点颜色 = 社区划分结果**——跑完社区或中心性算法后回到叠加层，这三个映射同时生效。

## 3. 模块二：网络基础拓扑指标（说明书 §4，平台"模块二：网络测量"）

> 本组算法全部推荐用**空手道俱乐部**（34 节点，投影上规模合适）。

### 3.1 拓扑摘要 —— 算法 `拓扑摘要`（topology.summary）｜§4.1、§4.4

- **操作**：空手道网络 → 选"拓扑摘要" → 默认参数运行。
- **指给学生看**：节点数、边数、**平均度**（§4.1）、密度、直径、**平均最短路径**、**平均聚类系数** 一张表全齐。
- **讲解话术**："平均度 4.6 说明平均每人认识 4~5 个人；聚类系数高、平均路径短——这就是小世界的雏形，下一个小实验验证它。"

### 3.2 Floyd 全源最短路 —— 算法 `Floyd 全源最短路`（paths.floyd）｜§4.2

- **操作**：选"Floyd 全源最短路" → 默认参数（`path_pair_limit=10000`）运行。
- **指给学生看**：
  1. **最短距离矩阵**；
  2. **任意两点的完整路径节点序列**（说明书重点输出）——现场挑两个学生名字对应的节点，把整条路径念出来："甲→乙→丙→丁"；
  3. **全网平均最短路径长度** L。
- **注意**：该算法 O(n³)，平台限制最大 500 节点——顺势讲算法复杂度与"为什么大网络用 BFS 近似"。

### 3.3 聚类系数 —— 算法 `聚类系数`（clustering.coefficient）｜§4.3

- **操作**：选"聚类系数" → 运行。
- **指给学生看**：单节点局部聚类系数表（排序后找"朋友圈最抱团"的人）+ 全网平均聚类系数。
- **讲解话术**：把平均聚类系数 C 和刚才拓扑摘要里的平均路径 L 记在黑板上，下一实验直接用。

### 3.4 经典网络模型：ER / WS / BA —— 三个算法连做，判别 §4.4 ｜§4.4

这是本模块最出彩的**对比实验**，建议做成一次连贯演示（每个 30 秒）：

| 算法 | 关键参数 | 运行后看什么 |
|---|---|---|
| `ER 随机图`（model.er） | n=30, p=0.1 | 度分布近似**泊松**、聚类系数极低 |
| `WS 小世界图`（model.ws） | n=30, k=4, p=0.1 | **高聚类 + 短路径**（小世界证据表） |
| `BA 无标度图`（model.ba） | n=30, m=2 | 度分布**幂律**、出现超高度枢纽节点 |

- **讲解话术**："刚才空手道网络的 C≈0.26、L≈2.4；ER 网络聚类系数只有 0.05——所以真实社交网络不是随机的；WS 保留高聚类又拉短路径；BA 则解释了为什么总有一两个'人缘王'。"
- 把三次运行的度分布图表并排截图，就是 §4.4 判别标准的现成课件。

## 4. 模块四：网络中心性测度（说明书 §5，平台"模块二：网络测量"）

> 全部用**空手道俱乐部**演示，六个指标连续跑，叠加层节点大小会随所选指标变化，视觉效果极好。

| 平台算法名 | 说明书 | 演示要点 |
|---|---|---|
| `度中心性`（centrality.degree） | §5.1 | 按值排序，指出"校长"和"教官"两个高点；叠加层节点大小直观可数 |
| `接近中心性`（centrality.closeness） | §5.2 | 强调"平均距离最短 = 消息传得最快"，不是朋友最多 |
| `中介中心性`（centrality.betweenness） | §5.3 | 排序后通常冒出一个度不高但中介性极高的节点——"桥梁人"，最出戏剧性 |
| `特征向量中心性`（centrality.eigenvector） | §5.4 | 对比度中心性排序差异："认识大佬比认识人多更重要" |
| `PageRank`（centrality.pagerank） | §5.5 | 参数 α（阻尼系数）0.85 默认；调到 0.5 再跑看排名变动，讲阻尼含义 |
| `HITS 枢纽-权威`（centrality.hits） | §5.6 | 输出 Hub/Authority 两列表——用"淘宝卖家(枢纽)/品牌(权威)"类比 |
| `度中心势`（centralization.degree） | §5.7 | 全网层面指标："这个网络的影响力集中吗"；注意它只支持无向图 |

**统一收尾动作**：把六列中心性结果让学生目测"谁在不同指标下都排前三"，引出"中心性是多维概念，选指标就是选理论视角"。

## 5. 模块五：社区发现（说明书 §6，平台"模块三：社区发现"）

> 主战场仍是空手道俱乐部（真实存在两个社区）；重叠社区换**海豚社群**。

### 5.1 先讲评判标准（§6.1–6.2，不占独立实验）

投影讲三句话：**强社区 / 弱社区 / 密度判定**怎么界定一个"社区"；**模块度 Q** 是通用打分器，Q 越大划分越清晰。后面的每个算法跑完都看它的 Q。

### 5.2 非重叠社区（§6.3）——建议按"从慢到快"顺序演示，突出方法演进

| 顺序 | 平台算法名 | 说明书 | 关键参数 | 演示与讲解要点 |
|---|---|---|---|---|
| ① | `KL 二分算法`（community.kernighan_lin） | §6.3.1 | `communities=2` | 只能二分 →"入门算法的局限" |
| ② | `凝聚层次聚类`（community.agglomerative） | §6.3.2 | 默认 | 看**聚类树**输出 |
| ③ | `分裂层次聚类`（community.divisive） | §6.3.2 | 默认 | 与凝聚式对照：自上而下 vs 自下而上 |
| ④ | `Girvan–Newman`（community.girvan_newman） | §6.3.3 | 默认 | 经典必讲：边介数→删边→迭代；空手道网络上正好分出两派 |
| ⑤ | `Fast Newman`（community.fast_newman） | §6.3.4 | 默认 | 对比 GN："以 Q 最大化为目标，更快更科学" |
| ⑥ | `Louvain`（community.louvain） | §6.3.5 | `resolution=1.0` | 工业界标配；讲双层迭代（局部移动+社区聚合） |
| ⑦ | `Leiden`（community.leiden） | §6.3.6 | `resolution=1.0` | 三阶迭代+精炼保证连通。**注意**：服务器未装 igraph 时平台会明示"回退为 Louvain"——这本身就是一个"平台不伪造结果"的教学点 |
| ⑧ | `LPA 标签传播`（community.lpa） | §6.3.7 | 默认 | **换 3 个不同种子连跑 3 次**，结果可能不同 → 讲"零参数但随机"的 trade-off |

**收尾必做**：`多算法模块度对比`（community.compare）——一键跑全部算法并排输出**模块度对比表 + 强/弱社区判定 + 密度判定**，直接回答"到底哪个算法分得好"，对应说明书 §6.7 统一输出。

**分辨率演示（§6.2 带分辨率模块度）**：Louvain 下 `resolution` 0.5 / 1.0 / 2.0 各跑一次 → 社区数从少到多，讲"多尺度社区结构"。

### 5.3 重叠社区（§6.4）—— 换海豚社群（62 节点）

| 平台算法名 | 说明书 | 关键参数 | 演示要点 |
|---|---|---|---|
| `CPM 派系过滤`（community.cpm） | §6.4.1 | `clique_size=3` | k-派系→相邻派系→重叠社区；把 clique_size 调 4 感受"准入变严、社区变少" |
| `LFM 局部适应度`（community.lfm） | §6.4.2 | `alpha=1.0` | 适应度函数贪心扩张；alpha 调大→社区更紧致 |
| `SLPA`（community.slpa） | §6.4.3 | `iterations=50, threshold=0.1` | "会说话的标签传播"；观察同一节点出现在两个社区——**重叠**本体 |

**指给学生看**：结果表中同一节点出现在多行/多社区，叠加层节点同时染色——这正是 CPM/SLPA 与 Louvain 的本质区别（§6.4 开头定义）。

### 5.4 深度学习社区（§6.5）—— 按平台能力如实演示

## 6. 模块六（上）：网络韧性（说明书 §7.1，平台"模块五：鲁棒性"）

### 网络鲁棒性攻击 —— 算法 `网络鲁棒性攻击`（robustness.attack）｜§7.1

- **数据**：空手道俱乐部（或 BA 无标度图，讲"无标度网络对蓄意攻击脆弱"更震撼）。
- **关键参数**：`strategy` 三选一：`random` 随机攻击 / `degree` 按度蓄意 / `betweenness` 按介数蓄意。
- **演示流程（三连跑）**：
  1. `random` 跑一次 → 看 **S(q) 曲线**缓慢下降；
  2. `degree` 跑一次 → 曲线断崖式下跌；
  3. `betweenness` 再跑 → 对比 **综合鲁棒性 R** 值。
- **指给学生看**：S(q) 曲线图（最大连通子图占比）+ R 值表 + 每轮删除的节点序列。
- **讲解话术**："随机挂掉 20% 节点网络还剩八成连通；但按度删前 5 个枢纽节点网络就碎了一地——这就是互联网'枢纽依赖'与疫情'超级传播者'的同一个数学结构。"（对应 §7.1 两个核心指标定义。）

## 7. 模块六（下）：链路预测（说明书 §7.2，平台"模块六：链路预测"）

> 用**海豚社群**；四个指标算法结构相同，可 20 分钟内连做。

| 平台算法名 | 说明书 | 演示要点 |
|---|---|---|
| `共同邻居 CN`（link_prediction.common_neighbors） | §7.2(1) | 最直觉："共同好友越多越可能认识" |
| `Jaccard 链路预测`（link_prediction.jaccard） | §7.2(2) | 与 CN 对比：标准化后大度节点不再霸榜 |
| `Adamic–Adar`（link_prediction.adamic_adar） | §7.2(3) | "给小圈子介绍人加权" |
| `资源分配 RA`（link_prediction.resource_allocation） | §7.2(4) | 稀疏网络首选 |

**统一参数讲解（每个算法都有，重点讲一次）**：
- `test_fraction=0.2`：**AUC 防泄漏评估**——先随机隐藏 20% 真实边再打分（说明书 §7.2(5)），强调"预测器不许偷看答案"，这是科学实验设计；
- `candidate_limit`：候选上限，超限拒绝运行（讲资源边界）；
- `top_k`：输出最可能成边的前 K 对。

**收尾**：四算法 AUC 并排抄在黑板 → "在你的数据上哪个指标最准？"引出"没有免费午餐"。

## 8. 模块七：观点动力学 + 动态社区（说明书 §8 与 §6.6）

> 用案例 `opinion-dynamics`（课堂意见网络）；观点取值 0~1，输出**观点轨迹图**与**观点方差**（§8.4 共识量化）。

| 平台算法名 | 说明书 | 关键参数 | 演示剧本 |
|---|---|---|---|
| `DeGroot`（opinion.degroot） | §8.1 | 默认（可自定义各节点初始意见） | 必然收敛到单一共识 → 轨迹图全部线汇合 |
| `Friedkin–Johnsen`（opinion.friedkin_johnsen） | §8.1(2) | `stubbornness=0.3` | 固执度>0 → 永远无法完全统一；调 0.8 看观点被"钉住" |
| `Deffuant`（opinion.deffuant） | §8.2 | `confidence=0.3, mu=0.5, steps=500` | **把 confidence 调到 0.1 再跑** → 群体两极分化，轨迹图裂成两簇——全场最震撼的一跑 |
| `HK`（opinion.hk） | §8.3 | `confidence=0.3` | 同步更新 → 分层极化，聚成几个观点团 |
| `动态社区事件`（community.dynamic） | §6.6 | 用案例 `trade-snapshots` | Jaccard 阈值 0.3，输出**延续/新生/消亡/分裂/合并**事件时间线 |

**讲解话术（Deffuant 极化）**："只把信任阈值从 0.3 降到 0.1——人们只跟观点相近的人聊天——一个班就分裂成两派。这四个参数就是舆情管理的全部秘密。"（对应 §8.2 交互前置约束 |x_i-x_j|≤ε。）

**观点方差（§8.4）**：每次运行都指一下方差曲线何时走平——"方差稳定 = 演化到达稳态"。

## 10. 学生作业布置建议（利用平台的可复现设计）

1. 每位学生自选一个真实关系网络（宿舍关系/班级选课/B 站互关……），以边表导入；
2. 完成：拓扑摘要 + 至少 3 种中心性 + 至少 2 种社区算法 + `多算法模块度对比`；
3. 每次运行**固定自己的随机种子**并下载**复现 ZIP**；
4. 提交：ZIP 包 + 一页"解释发现"（哪个节点最核心？哪个算法模块度最高？为什么？）；
5. 教师验收：解压 ZIP 核对 provenance.json 的参数哈希与图哈希——**结果可复现即成绩可复核**。

## 11. 常见课堂突发情况

| 现象 | 原因与说法 |
|---|---|
| 提示"算法能力不可用"（GCN/GAT） | 服务器未启用 ML 镜像，平台如实报告而非伪造结果；需要时联系管理员启用 ml profile |
| Leiden 结果与 Louvain 一致并带提示 | 未装 igraph 时自动回退，提示信息会明示 |
| 运行报 429 限流 | 匿名限流：标准算法 120 次/小时、重算法 30 次/小时/IP——课堂 40 人同时轰炸可能触发，稍等或分批演示 |
| 上传被拒 | 仅接受 TXT/CSV/XLSX/JSON/GraphML/GEXF，≤20MB，且 XLSX 禁宏/禁外部链接 |
| 两人跑同一实验结果不同 | 检查随机种子是否一致；种子+参数+算法版本一致则结果必须一致（可复现性演示点） |
| 历史记录消失 | 运行数据 2 小时自动清理、历史只存本机浏览器——隐私设计，不是故障 |
